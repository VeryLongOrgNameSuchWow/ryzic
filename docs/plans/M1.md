## 0. Open question

**Auto-leave on idle?** When `QueueEndEvent` fires (queue done, voice still connected), should the bot disconnect after N minutes of silence?

**Default chosen, awaiting confirmation:** auto-leave after **5 minutes** idle. Hardcoded constant, no env var until someone asks. Sensible Discord etiquette default — bots sitting in voice is annoying. Override or disable trivially in code if the user prefers manual `/leave` only.

(All four prior open questions are decisions, not questions, and locked in the relevant sections: Lavalink server v4.x + youtube-source plugin, video-id-keyed cache collapses URL variants, `/play` appends to active playlist, single-shard self-hosted assumption.)

## 3. Per-command UX

Embed builders live in `ux.py`. One-shot strings (`"Nothing is playing."`) live inline at the command call site for locality of reference. All errors **ephemeral** unless noted.

### Cross-cutting

- **All commands**: `dm_enabled=False` at command registration. `/play` in DM never reaches handler.
- **`/skip`, `/pause`, `/resume`, `/leave`**: first line is `if not await ensure_same_voice(ctx): return`. Helper sends ephemeral `"Join <#{bot_channel_id}> to use this."` if user not in bot's voice channel.
- **Stage channels rejected**: detect `channel.type == hikari.ChannelType.GUILD_STAGE` in `/play`; ephemeral `"Stage channels aren't supported. Use a regular voice channel."`
- **All embeds**: titles/uploaders escape Discord markdown via `escape_markdown()` helper that backslash-escapes `[ ] ( ) * _ ~ ` `` ` ``  `|`. All strings truncated to Discord's limits (description 4096, field 1024, footer 2048) by a single `safe_truncate()` helper.

### `/play <url>`

- Param: `url: str` (1–500 chars).
- URL validator (`url_validator.py`):
  ```python
  ALLOWED_HOSTS = {"youtube.com", "www.youtube.com", "m.youtube.com",
                   "music.youtube.com", "youtu.be"}
  def is_supported_url(url: str) -> bool:
      try: p = urllib.parse.urlparse(url)
      except ValueError: return False
      return p.scheme == "https" and p.hostname in ALLOWED_HOSTS
  ```
  (Fixes review HIGH-1: regex-based validator allowed `youtube.com.evil.com`.)
- Flow: defer (public) → URL-shape detect (`list=` query → playlist branch, else track) → resolve via yt-dlp → reject livestreams → ensure voice connection → enqueue → `player.play()` if `not is_playing`.
- **Livestream rejection** (HIGH-2): after `extract_info`, if `info.get("is_live")` or `info.get("live_status") in {"is_live", "is_upcoming"}` → ephemeral `"Livestreams are not supported in this version."`
- **Queue overflow**: cap 500 tracks per guild. Overflow → ephemeral `"Queue is full ({n}/500). Wait for some tracks to finish."`
- **`/play` while paused**: enqueues only; does NOT unpause. User must `/resume`.
- **Concrete responses**:
  - Single track success: embed titled `"Queued"`, description `"[**{escaped_title}**]({url})"`, footer `"by {escaped_uploader} · {mm:ss} · position {n} in queue"`. If queue empty + idle: `"… · playing now"`.
  - Playlist success: title `"Queued playlist"`, description `"**{escaped_title}** — {N} tracks ({total_mm:ss})"`, footer `"requested by {user}"`.
  - Playlist partial-failure: same + `"{X} tracks could not be loaded"` footer line.
  - Playlist 100% failed but cache exists: title `"Queued playlist (offline metadata)"`, footer warns `"yt-dlp could not refresh; using cache from {timestamp}. Tracks may fail individually."`
  - User not in voice: ephemeral `"Join a voice channel first."`
  - URL not allowed: ephemeral `"Only YouTube URLs are supported."`
  - Bot in different channel (HIGH-3 fix): ephemeral `"I'm already playing in <#{other_id}>. Join that channel."` — drops the bogus `/leave` suggestion (which required same-channel anyway).
  - Bot lacks Connect/Speak: ephemeral `"I don't have permission to join <#{id}>."`
  - Empty/private playlist: ephemeral `"That playlist is empty or private."`
  - **Friendly yt-dlp error mapping** (review §3 age-restricted item): match known patterns:
    - `"Sign in to confirm your age"` → `"That video is age-restricted and can't be played."`
    - `"Private video"` → `"That video is private."`
    - `"Video unavailable"` (region msg) → `"That video is not available in this region."`
    - default fallback: `` "Could not load that URL. yt-dlp said: ``{first_line}``" `` (200 char cap, backticks stripped from `first_line`)
  - Lavalink down: ephemeral `"Audio service is down. Try again in a minute."`
  - Two `/play` for same video URL race: per-video lock (§4) ensures one download; both interactions get success.

### `/skip`
- Success: public `"Skipped **{escaped_title}**."` + `" Queue is empty."` if queue now empty.
- **Skip while paused**: skip advances; new track stays paused; user must `/resume`.
- Errors: nothing playing → `"Nothing is playing."`

### `/queue`
- No voice-channel requirement.
- Success: embed titled `"Queue ({N} tracks · {total_mm:ss})"` with **Now playing** field showing `"[**{title}**]({url})"` and progress `"{pos_mm:ss} / {len_mm:ss}"` — appended `" (paused)"` if `player.paused`. Description: up to first 10 entries `{i}. [{title}]({url}) — {mm:ss} (req. by {user})`. Beyond 10: `"… and {N-10} more"`.
- Edge: nothing playing + queue empty → ephemeral `"Queue is empty and nothing is playing."`
- Edge: playing + queue empty → embed shows only Now playing.

### `/pause`
- Success: public `"Paused."` Errors: not playing → `"Nothing is playing."`; already paused → `"Already paused. Use /resume."`

### `/resume`
- Success: public `"Resumed."` Errors: not playing → `"Nothing is playing."`; not paused → `"Already playing. Use /pause to pause."`

### `/leave`
- Success: public `"Left voice channel. Queue cleared."` Errors: bot not in voice → `"I'm not in a voice channel."`

### Auto-leave (default 5min — confirm in §0)
- On `QueueEndEvent` for a guild, schedule a 5-minute timer. If a new track starts before it fires, cancel. If timer fires and queue still empty + voice connected, disconnect + post in `last_play_channel`: `"Idle for 5 minutes — disconnecting."`

### Voice channel deleted / connection lost
- On `WebSocketClosedEvent` code 4014 OR `NodeDisconnectedEvent`: clear queue, post in `last_play_channel`: `"Voice connection lost. Queue cleared."`

## 4. Audio cache subsystem

**Storage layout** (under `RYZIC_CACHE_DIR`, default `./.cache`):
```
.cache/
  audio/{video_id[:2]}/{video_id}.{ext}
  playlists/{playlist_id}.json
  index.sqlite
  tmp/{video_id}.{ext}.partial
```

**No sidecar `.json`** per `M1-simplify.md` §4 — metadata lives in sqlite columns: `title TEXT, uploader TEXT, duration_ms INTEGER, fetched_at INTEGER`.

**Path safety**: `video_id` matched against `^[A-Za-z0-9_-]{6,20}$` *before* path construction. After construction, `path.relative_to(cache_root)` must succeed; else `InvalidVideoID`.

**sqlite schema** (one table):
```sql
CREATE TABLE entries (
  video_id TEXT PRIMARY KEY,
  rel_path TEXT NOT NULL,          -- relative to cache_root
  ext TEXT NOT NULL,
  bytes INTEGER NOT NULL,
  title TEXT NOT NULL,
  uploader TEXT NOT NULL,
  duration_ms INTEGER NOT NULL,
  fetched_at INTEGER NOT NULL,
  last_used_ts INTEGER NOT NULL
);
CREATE INDEX entries_lru ON entries(last_used_ts);
```

Open with `aiosqlite`, `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL` (review §4 sqlite write contention).

**LRU + size cap**:
- On hit: `UPDATE entries SET last_used_ts = ? WHERE video_id = ?`.
- On insert: insert row, then evict-loop while `SUM(bytes) > MAX_BYTES`, oldest `last_used_ts` first; for each evicted, `unlink` audio file. Skip rows with `_in_use[video_id] > 0`.
- **No TTL** — cached files survive yt-dlp breakage (deliberate, per spec).

**Concurrent-download protection**:
- `_locks: dict[str, asyncio.Lock]` keyed by `video_id`. Locks are leaked deliberately (per `M1-simplify.md` §10 keep-list — bytes are trivial).
- `_in_use: collections.Counter[str]` (review §4 — same video may be queued multiple times; `set` was wrong).
- `async def get_or_download(video_id, url) -> Path`:
  1. Check sqlite. If present + file exists on disk → touch `last_used_ts`, **`_in_use[video_id] += 1`**, return path.
  2. Else acquire `_locks[video_id]` (lazy-create).
  3. Re-check sqlite under lock (double-checked locking).
  4. Download to `tmp/`. On success: `os.replace(tmp → final)`, INSERT row, **`_in_use[video_id] += 1` BEFORE running evictor**, run evictor (now respects in-use), return path.
  5. On failure: `tmp_path.unlink(missing_ok=True)`; raise.

(Review §4 race: `_in_use += 1` MUST happen before returning the path, NOT when Lavalink loads — otherwise eviction can delete the just-finished file in the gap.)

- Caller decrements via `await cache.release(video_id)` on `TrackEndEvent`. Caller MUST release on Lavalink load failure too.
- On startup: clear `_in_use` (everything was released by restart anyway).
- On `WebSocketClosedEvent` / `QueueEndEvent` for a guild: walk that guild's queue and decrement each in-use entry (review §4 missed-event leak).

**Orphan sweep** (review §4 race-with-eviction): on startup, walk `audio/` directory; for each file with no sqlite row AND `mtime > 1h ago` (avoids racing with concurrent download), unlink.

**Surfacing to Lavalink**: pass absolute path as load query: `await player.node.get_tracks(str(path))`. Lavalink's `LocalAudioSourceManager` (`server.sources.local: true`) loads it.

**Volume identical-path constraint**: ryzic and lavalink containers BOTH mount the cache volume at `/var/cache/ryzic`. Lavalink's mount is `:ro`.

## 5. Playlist metadata cache

Module functions in `playlist_cache.py` — no class:
```python
async def read(playlist_id: str, cache_root: Path) -> PlaylistInfo | None: ...
async def write(playlist_id: str, info: PlaylistInfo, cache_root: Path) -> None: ...
def is_stale(info: PlaylistInfo) -> bool: ...    # >24h old
```

`playlist_id` validated against `^[A-Za-z0-9_-]{10,50}$`. JSON file at `playlists/{playlist_id}.json`. TTL hardcoded at 24h (no env var per `M1-simplify.md` §3).

**Lookup flow**:
1. Always call yt-dlp `extract_info(url, extract_flat=True)` first.
2. On success: `write()`, return result.
3. On any yt-dlp exception: `read()`; if found, return regardless of TTL but emit `is_stale()` flag for the embed warning.
4. If neither: raise `FetchFailed`.

## 6. yt-dlp wrapper — interface and security

**Public interface** (`ytdlp.py` — module functions, no class per `M1-simplify.md` §10):
```python
@dataclass(frozen=True)
class TrackInfo: video_id: str; url: str; title: str; uploader: str; duration_ms: int
@dataclass(frozen=True)
class PlaylistInfo: playlist_id: str; title: str; entries: list[TrackInfo]

async def resolve_track(url: str) -> TrackInfo: ...
async def resolve_playlist(url: str) -> PlaylistInfo: ...
async def download(url: str, dest: Path) -> None: ...
```

(Review §1 SRP: split union return into two methods; URL-shape detection lives in `/play`.)

All sync calls run via `asyncio.to_thread(_sync_call, ...)` wrapping `with YoutubeDL(opts) as ydl: ydl.extract_info(...)`. **Embedded Python API; no subprocess; no shell.**

**Frozen `YoutubeDL` opts**:
```python
{
  "format": "bestaudio[ext=m4a]/bestaudio[ext=opus]/bestaudio[ext=webm]/bestaudio",
  "noplaylist": True,                    # overridden False for playlist URLs
  "extract_flat": False,                 # overridden True for playlist-listing
  "quiet": True, "no_warnings": True, "no_color": True,
  "outtmpl": str(dest_path),             # absolute, sandbox-validated
  "paths": {"home": str(cache_root / "tmp")},
  "restrictfilenames": True,
  "concurrent_fragment_downloads": 1,
  "geo_bypass": False,
  "max_filesize": 500_000_000,           # 500MB per-track cap
  "playlist_items": "1-1000",            # 1000-track playlist cap
  "cookiefile": None,                    # DO NOT enable; out of M1 scope, security-sensitive
  "logger": _quiet_logger,
}
```

Format-priority constrains to known-good Lavaplayer codecs (review §6 LOAD_FAILED on exotic codecs).

**Security review** (additions in **bold**):

1. **Argv injection**: N/A (embedded API).
2. **Path traversal via `outtmpl`**: `dest_path` built from validated `video_id`; `restrictfilenames=True` defense-in-depth.
3. **URL allowlist** (HIGH-1 fix): `urlparse + hostname allowlist + https-only` in `url_validator.py` BEFORE yt-dlp sees the URL.
4. **Pickle/eval RCE**: yt-dlp doesn't pickle user input; JS interp is YouTube-served only.
5. **Disk-fill DoS**: bounded by `RYZIC_CACHE_MAX_GB` + 500MB per-track + 1000-track playlist cap.
6. **Livestream DoS** (HIGH-2 fix): post-extract check `info.get("is_live")` and `info.get("live_status") in {"is_live", "is_upcoming"}`. Reject before download.
7. **Cache poisoning**: `video_id` is yt-dlp-returned post-fetch; charset bounded by regex.
8. **yt-dlp as attack surface**: pin floor only; rely on `uv lock`. Follow-up issue for renovate/dependabot.
9. **Network egress / `/play` spam**: out of M1 scope; doc note in README.
10. **Discord markdown injection in error embeds**: strip backticks from yt-dlp error strings BEFORE wrapping in inline code; `escape_markdown` on titles/uploaders before formatting as markdown links (review §5).
11. **Embed length limits**: `safe_truncate(str, max_chars)` enforced in `ux.py`; no embed field exceeds Discord's hard limits (review §5).
12. **Lavalink local-source future-proofing**: doc rule — "All paths passed to Lavalink MUST be derived from a validated `video_id` via `audio_cache.path_for(video_id)`. New code paths must extend `_validate_path(p)` enforcing `p.relative_to(cache_root)`." (review §5).
13. **Cookies disabled and documented**: `cookiefile: None` explicit; comment forbids enabling without a security review.

Errors → `FetchFailed(str)` with first line of `DownloadError`; everything else → `FetchFailed("internal error: ...")` + full trace at ERROR.

## 7. Lavalink integration (the hazard zone)

References — Devoxin/Lavalink.py issues:
- #153 (open Apr 2026): `AssertionError: player.current is not None` on rapid `player.play()`. Mitigated below.
- #144: stuck-track. Mitigated below.
- #150: autocomplete N/A in M1.

**The hikari ↔ lavalink.py seam.** `lavalink.py` ships no hikari adapter; bridge is two listeners translating hikari events into discord.py-shaped dicts:

```python
@bot.listen(hikari.VoiceServerUpdateEvent)
async def _vs_server(event):
    if ll_client is None: return                       # review §6 node-not-ready guard
    await ll_client.voice_update_handler({
        "t": "VOICE_SERVER_UPDATE",
        "d": {"guild_id": event.guild_id,
              "endpoint": event.endpoint.removeprefix("wss://"),   # review §6 not [6:]
              "token": event.token},
    })

@bot.listen(hikari.VoiceStateUpdateEvent)
async def _vs_state(event):
    if ll_client is None: return
    await ll_client.voice_update_handler({
        "t": "VOICE_STATE_UPDATE",
        "d": {"guild_id": event.state.guild_id, "user_id": event.state.user_id,
              "channel_id": event.state.channel_id, "session_id": event.state.session_id},
    })
```

Joining/leaving voice via hikari directly: `await bot.update_voice_state(guild_id, channel_id, self_deaf=True)`.

**Voice handshake race fix** (review §6): after `update_voice_state(...)`, await an internal `_voice_ready_events: dict[int, asyncio.Event]` set by the `VoiceStateUpdateEvent` listener for our own user, with 5s timeout. THEN call `player.play()`. Otherwise `player.play()` may fire before lavalink.py has the voice connection and silently play nothing.

**Required hikari intents**: `GUILDS | GUILD_VOICE_STATES`. No member/message-content/presence intents.

**Player lifecycle**:
- `player = ll_client.player_manager.create(guild_id=...)` — idempotent.
- `player.add(track=..., requester=user_id)`.
- `await player.play()` only if `not player.is_playing`.
- `await player.skip()` to skip.
- `await player.set_pause(True/False)`.
- Leave: `await player.stop()` + `player.queue.clear()` + `bot.update_voice_state(guild_id, None)`.

**Issue #153 mitigation**: never `player.play()` from `TrackEndEvent` handler (Lavalink advances queue); `/play` calls `player.play()` only when `not is_playing` and AFTER `player.add()`. Skip uses `player.skip()`, never `stop()` then `play()`.

**Issue #144 mitigation** (`TrackStuckEvent`): log; `await player.skip()`; post in `last_play_channel`: `"Track **{title}** got stuck and was skipped."`

**Node bootstrap**: subscribe `hikari.ShardReadyEvent` once; construct `lavalink.Client(bot.get_me().id)`; add node `host=LAVALINK_HOST, port=LAVALINK_PORT, password=LAVALINK_PASSWORD, region="us"`; register `EventHandler` via `client.add_event_hooks(...)`; stash in `lightbulb.di` registry.

**Local file loading**: Lavalink's `LocalAudioSourceManager` accepts plain absolute filesystem path (no `file://`).

**EventHandler hooks**:
- `TrackStartEvent` — log; record `current_track`.
- `TrackEndEvent` — log; `await audio_cache.release(video_id)` for the ended track.
- `TrackExceptionEvent` — log warn; `await audio_cache.release(video_id)`; post `"Track **{title}** failed: {reason}. Skipping."`
- `TrackStuckEvent` — see #144 mitigation.
- `QueueEndEvent` — log; **start auto-leave 5min timer** (see §3 auto-leave).
- `WebSocketClosedEvent` (4014) — clear queue + decrement in-use for this guild's queue + notify last_play_channel (review §3 voice-channel-deleted).
- **`NodeDisconnectedEvent`** (review §6): mark all players invalid; clear queues; notify last-known channels: `"Audio service disconnected. Reconnecting..."`. On `NodeConnectedEvent`: log; users can `/play` again to recreate.

**Lightbulb v3 port**: official `hikari_music.py` example is v2. Rewrite to v3 idioms (declarative `lightbulb.SlashCommand`, `lightbulb.Loader`, `client.di` registry, `client.start` from `hikari.StartingEvent`). Voice listeners subscribed on `GatewayBot` directly in `bot.py`, not inside an extension Loader.

## 8. Per-guild state model

No class. Inline state in `lavalink_glue.py`:
```python
last_play_channel: dict[int, int] = {}     # guild_id → last text channel of /play
auto_leave_tasks: dict[int, asyncio.Task] = {}   # for cancellable 5min timers
_voice_ready_events: dict[int, asyncio.Event] = {}  # for voice-handshake race fix
```

(`GuildState` dataclass + `GuildStateRegistry` removed per `M1-simplify.md` §2 and review §1; the original two fields were `voice_channel_id` (derivable from `bot.cache.get_voice_state(guild_id, bot_user_id)`) and `last_play_channel_id` — only the latter needs storage.)

Queue + player + paused state live inside `lavalink.py`'s PlayerManager — we don't shadow them.

**Restart behavior**: in-memory only. All state dies on restart. Cached audio files survive (the cache's whole purpose); per-guild queue does not. Deliberate KISS choice.

## Lavalink.py traps surfaced during planning (recap, see §7)

- Open bug #153 (rapid-play `AssertionError`, unfixed Apr 2026) — mitigated by never calling `play()` from `TrackEndEvent` and only when `not is_playing`.
- Stuck-track #144 — mitigated via `TrackStuckEvent` handler.
- No hikari adapter ships with the lib — manual two-listener bridge (§7).
- Canonical example is lightbulb v2 — must be ported to v3.
- YouTube source deprecated in Lavalink server v4 — `youtube-source` plugin mandatory.
- Voice handshake race after `update_voice_state` — wait for our own `VoiceStateUpdateEvent` (5s timeout) before `player.play()`.
- Node disconnect (vs Discord-side 4014) needs separate handler — `NodeDisconnectedEvent` / `NodeConnectedEvent`.
